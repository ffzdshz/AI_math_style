# 乱序子表 Run A 执行用时对照（2026-11-06）

## 口径与结论

三组均为 13 卷、465 个相同命题；逐命题取最终采用的成功执行记录 `per_proposition_execution` 末条的 `total_wall_time_seconds`，然后分别汇总。失败及未被最终采用的执行尝试、重试等待和队列停顿不计入这些统计。本次三组每个命题均只有 1 条最终采用的成功记录。
该指标是并发 worker 的执行耗时之和，**不是一整卷或整批的实际墙钟完成时间**。计时从完成 context/table 准备之后开始，仍含 CLI 启动、模型请求、工具调用、成功请求内网络延迟与等待，无法从现有记录精确扣除这些网络等待或估计无网络故障时的整批完工时间。
因此它可以回答“已采用的成功执行是否整体耗时较多”，不能严格回答排除网络后的真实计算耗时或反事实总工期；观察性比较不能证明差异由表格机制造成。

## 重要限制

- 三组并非同一时刻随机交叉运行；上游负载、网络状况、输出长度、模型服务及工具调用等均可能不同。
- 旧版此前卷命题只提供编号，新版表中可读前卷完整陈述；新版还使用表格访问工具。因此不是单变量对照。
- 并发上限和调度实际情况也影响真实工期；新版和 anti-grounding 的 ExecutionGate 对有 run_dir 的 worker 设置 30 秒启动间隔，旧版没有同一门控。上述逐次成功执行计时不包含该等待，不能推导整批工期。
- 原始 raw 记录中有失败条目；这些不能全部归因于网络。成功记录也可能经历网络变慢，现有计时未将其分离。
- 结构/引用顺序审计通过不等于数学正确性已验证，CLI 请求配置也不是上游实际模型权重的独立鉴证。
